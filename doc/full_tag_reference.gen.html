List of Tags

The following table shows all available tags.

Tag Name Type Parameter Example Description
COMMENT preprocessor directive 
[COMMENT] This can be used for commenting templates.
 A line starting with this tag is suppressed and can be used to comment the template without affecting the output. Any whitespace surrounding the statement is ignored.
INCLUDE preprocessor directive Path and name of the file to include 
[INCLUDE]["file.h"][TRIM]
 A line starting with this tag causes the intermediate processing of the file specified by the parameter. The include tag can be placed anywhere in the template file. If a relative path is provided it is relative to the template file containing the INCLUDE tag. If the file is not found there the include directories are searched for a file with the relative path.
SET_MARKUP preprocessor directive Prefix, Postfix 
[SET_MARKUP]["<<",">>"]
 Changes the markup prefix and postfix used for the next lines of the template file after the line containing the statement and for subsequently included files. Leading whitespace for a prefix and trailing whitespace for a postfix is not allowed. The markup is only changed for the scope of the current file and subsequently included files. It has no effect on a template file that included a file changing the markup.
TRIM preprocessor directive 
    [BEGIN][TRIM]
 Leading and trailing white space characters (including the new line character) and the tag itself are removed from a line ending with the tag. The main purpose is to allow a better readable formatting of the macros in the template file. A single line macro is not extended to the next line when using trim.
TRIM_LEFT preprocessor directive 
    [ENTRY]["List"][TRIM_LEFT]
 Leading white space characters and the tag itself are removed from a line ending with the tag. The main purpose is to allow a better readable formatting of the macros in the template file.
TRIM_RIGHT preprocessor directive 
    [ENTRY]["List"][TRIM_RIGHT]
Trailing white space characters (including the new line character) and the tag itself are removed from a line ending with the tag. The main purpose is to allow a better readable formatting of the macros in the template file. A single line macro is not extended to the next line when using trim left.
PART preprocessor directive The label of the part to expand. Optional: The left padding characters and the total count of characters to pad. 
    [ENTRY]["List"][PART]["LengthyAdditionalTagsAndText"]
 PART expands to a previously defined fragment of a template, e.g. a fragment of a macro. This useful if macros get very large, parts of a macro need to be repeated often or if you need to inject parameters into a macro. You can use PART_BEGIN and PART_END to define a part. Additional padding can be inserted after new line character padding the beginning of a line. If more than one character is provided, the rightmost character is used for padding. All additional characters are always added leftmost. The characters passed for padding must not contain characters with ASCII code less than 32, e.g. new line or tab. If the count is ommited the passed string is used for padding left as is. If the character count is zero nothing is added at all.
PART_BEGIN processing directive The label of the part to add. 
[PART_BEGIN]["myLabel"][CONTAINS]["xyz"]more[PART_END]
 The PART_BEGIN and PART_END tags are used to declare a fragment of a template can span multiple lines or is located inside a single line. The part identified by its label can be inserted later using the PART tag. Part blocks cannot be nested. Part blocks cannot be defined inside macro blocks defined by MACRO_BEGIN and MACRO_END. You can use delay dots together with PART_BEGIN and PART_END to define parts with data from one table, e.g. parameters, and use the parts for processing another table. Redefining a part with the same label is not allowed. You can use PART_REMOVE to delete a previous definition. If PART_BEGIN is encountered the previous content of the line is processed and can form a macro. Parts are available from definition to the end of processing of the main file, unless the are removed by using PART_REMOVE. Parts can be defined in include files (see INCLUDE tag) and are available in subsequently included files.
PART_END processing directive 
[PART_BEGIN]["myLabel"][CONTAINS]["xyz"]more[PART_END]
 Closes a part block.
PART_LAZY processing directive The label of the part to expand. Optional: The left padding characters and the total count of characters to pad. 
[PART_BEGIN]["L1"][CONTAINS]["xyz"][PART_LAZY]["L2"][PART_END]
 Behaves exactly like the part tag. The difference is the time the PART_LAZY tag is evaluated when located in another part block. A PART tag is expanded immediately into the enclosing part block. PART_LAZY is expanded when the enclosing PART block is expanded.
PART_PADDING processing directive 
[PART_BEGIN]["L1"]...[PART_PADDING]...[PART_END]
 PART_PADDING is replaced by the padding text applied when expanding a PART or PART_LAZY tag.
PART_REMOVE processing directive The label of the part to remove. 
[PART_REMOVE]["LengthyAdditionalTagsAndText"]
 Removes a part identified by its label that has been defined previously. If the part does not exist or already has been removed nothing is done.
SET_RECURSION_LEVEL_LIMIT processing directive 
[SET_RECURSION_LEVEL_LIMIT.][TRIM]
 This directive can be used to limit the recursion level when using multistage macro expressions. This is useful when debugging. Insert zero or more delay dots to indicate the last level to process. The set recursion level limit directive can only be used at the beginning of a line and outside of a macro. This tag is always processed.
SET_RECURSION_LEVEL_LIMIT_OFF processing directive 
[SET_RECURSION_LEVEL_LIMIT_OFF][TRIM]
 This directive can be used to remove a recursion level limit. This tag is always processed. Delay dots have no effect.
TABLE_BEGIN processing directive The label of the table to add. Optional: The delimiting characters. Characters used for commenting. Properties of the table. Characters for text item quote. 
[TABLE_BEGIN]["myTable","","#","pad-rows"]Numbers;1;2;5[TABLE_END]
 Can be used to define a table block that contains a comma-separated-values table using a single character as delimiter to separate the items of a table. Parameter 1 is label of the table. Optional parameter 2 defines the delimiter. The default delimiter is ';'. Optional parameter 3 define a list of characters as string that mark commented lines in CSV-files when found at the beginning of a line. Per default no comment chars are used. Optional parameter 4 can be used to pass additional directions. Possible values are top-down, left-to-right, pad-rows, csv-ignore-quotes and permanent, separated by a semicolon. 'top-down' and 'left-to-right' limit the allowed reading direction of the table. The default is reading both directions. If 'permanent' is provided the table will be exported by the template file. The default behaviour is removing tables defined by a template file at the end of processing of the main file. If 'pad-rows' is provided. Optional parameter 4 can be used to pass characters that are used for putting text items in quotes. The default is the double quote character. the loader automatically fills missing row items at the end of a row with an empty string. In the default behaviour this causes an error otherwise. Table blocks cannot be nested. Table blocks can only contain text. This includes tags containing a delay dot.
TABLE_END processing directive 
[TABLE_BEGIN]["myTable"]Numbers;1;2;5[TABLE_END]
 Closes a table block.
TABLE_LOAD processing directive The filename. The label of the table to add. Optional: The delimiting characters. Characters used for commenting. Properties of the table. Characters for text item quote. 
[TABLE_LOAD]["dir/file.csv","myTable","","#","pad-rows"]
 Loads a table from a csv file. Otherwise TABLE_LOAD behaves like a table block. The parameters 2-5 match exactly like the TABLE_BEGIN parameters 1-4. See TABLE_BEGIN for more information. If a relative path is provided it is relative to the template file containing the TABLE_LOAD tag. If the file is not found there the include directories are searched for a file with the relative path.
TABLE_REMOVE processing directive The label of the table to remove. 
[TABLE_REMOVE]["myTable"]
 Removes a table identified by its label that has been defined previously. If the table does not exist or already has been removed nothing is done.
ANY macro keyword 
[ENTRY]["Description"][ANY]
 The substitution succeeds in any case if the row or column is contained in the table.
AS_VOLATILE macro keyword 
[ENTRY]["Description"][AS_VOLATILE]
 It indicates that the row or column can be missing in the table. The entry heading is therefore not used for determining the reading direction for the macro and for determining which table to read.
BEGIN macro keyword 
foo([BEGIN]"[ENTRY]["Parameter Name"]"[OR]"default"[END]);
 The BEGIN and END tags mark a macro block. A macro block is used conjunction with the OR keyword. Macro blocks can be nested.
BLOCK_FORMAT macro keyword The block width. 
[ENTRY]["Data"][BLOCK_FORMAT][20]
 Formats the expanded item text into a text block of the given width by inserting new line characters.
CALC macro keyword The arithmetic expression. 
[ENTRY]["Number"][CALC]["a+1"]
 Supports integer calculation supporting the operators +-/*%, parentheses () and the unary sign operators +-. The computation is performed using 64 Bit signed integer values. Supports the variable a. The variable a is replaced with the epression from the ENTRY, COUNT or INDEX tag. Overflow is not explicitly handled and must be avoided.
CONTAINS macro keyword Text to match 
[ENTRY]["File"][CONTAINS][".tpl."]
 The substitution succeeds if the entry contains the specified text.
COUNT macro keyword 
[COUNT]
 The tag is substituted with the count of successful substitutions of the current macro.
END macro keyword 
foo([BEGIN]"[ENTRY]["Parameter Name"]"[OR]"default"[END]);
 The tag ends a macro block.
ENDS_WITH macro keyword Text to match 
[ENTRY]["File"][ENDS_WITH][".exe"]
 The substitution succeeds if the entry ends with the specified text.
ENTRY macro keyword Column or row name 
[ENTRY]["State 1"]
 Is substituted successfully with the text of current entry in the specified row or column, if the entry is not empty. Multiple columns or rows having the same name are substituted in the order they appear in the table. This default behavior can be overridden by applying constraints. The default constraint is [NOT][EQUALS][""].
EQUALS macro keyword Text to match 
[ENTRY]["Data"][EQUALS]["Machine"]
 The substitution succeeds if the specified text matches.
ERROR macro keyword Error message 
[BEGIN][ENTRY]["Param"][OR][ERROR]["Missing Parameter."][END]
 The processing aborts with error when this tag is expanded.
FIRST_TIME macro keyword 
MyClass() [BEGIN][IF][FIRST_TIME]:[OR],[END][ENTRY]["Initializer"]
 A macro block or alternative containing this tag can only be expanded successfully for the first time.
FLUSH macro keyword 
[ENTRY]["Data"][FLUSH]
 The substitution succeeds if one column or row of multiple columns or rows can be substituted successfully, causing output for all columns or rows.
FOR_ALL macro keyword 
[ENTRY]["Data"][FOR_ALL]
 The substitution succeeds if all entries of multiple columns or rows with same name can be substituted successfully.
HTML_ESCAPE macro keyword 
[ENTRY]["Data"][HTML_ESCAPE]
 Escapes the following list of characters: <&"'`(){}[]!@$%=+>
IF macro keyword 
[IF][ENTRY]["State 1"][IF][NOT][ENTRY]["State 2"]
 Used for checking if a substitution can be expanded successfully.
IGNORE_CASE macro keyword 
[ENTRY]["File"][REPLACE][".tpl.", ".gen."][IGNORE_CASE]
 Causes replace operations to be performed ignoring case.
INDEX macro keyword 
[INDEX]
 The tag is substituted with the one based index of the current row or column being read.
LAST_TIME macro keyword 
[LAST_TIME]
 A macro block containing this keyword can only be expanded successfully for the last time.
MACRO_BEGIN macro keyword 
foo([BEGIN]"[ENTRY]["Parameter Name"]"[OR]"default"[END]);
 The MACRO_BEGIN and MACRO_END tags are used to declare a macro that spans multiple lines or to declare a macro that is expanded inside a single line.
MACRO_END macro keyword 
foo([BEGIN]"[ENTRY]["Parameter Name"]"[OR]"default"[END]);
 The tag ends a macro.
MATCHES_REGEX macro keyword Regular expression to match 
[ENTRY]["File"][MATCHES_REGEX]['(.*)\.exe']
 The substitution succeeds if the specified regular expression matches.
MERGE macro keyword Separator text 
[ENTRY]["Data"][MERGE][", "]
 The separator text is inserted between the entries of multiple columns or rows with the same name.
NOT macro keyword 
[ENTRY]["Machine"][NOT][EQUALS]["State machine"]
 This tag negates the meaning of the next modifier.
OR macro keyword 
[ENTRY]["State 1"][OR][ENTRY]["State 2"]
 This tag splits a macro block into multiple alternatives. Only the first successfully expanded alternative is used.
PAD_LEFT macro keyword The padding characters and the count(s) of characters to pad 
[ENTRY]["Data"][PAD_LEFT][" ", 40]
 Pads the left side of the expanded item text according to given number of characters if needed. The character count can be provided more than once when padding multiple lines. The first provided number of characters is used for padding the first line, then next for the next line and so on. The last given number of characters is used for all following lines. If the character count starts with a plus sign the number of characters is prepended otherwise the line is padded until the number of given characters has been reached. If more than one character is provided, the rightmost character is used for padding. M26 Additional characters are included in the given padding width. If the character count is zero nothing is added at all. The characters passed for padding must not contain characters with ASCII code less than 32, e.g. new line or tab.
PAD_RIGHT macro keyword The padding characters and the count(s) of characters to pad 
[ENTRY]["Data"][PAD_RIGHT][" ", 40]
 Pads the right side of the expanded item text according to given number of characters if needed. The character count can be provided more than once when padding multiple lines. The first provided number of characters is used for padding the first line, then next for the next line and so on. The last given number of characters is used for all following lines. If the character count starts with a plus sign the number of characters is appended otherwise the line is padded until the number of given characters has been reached. If more than one character is provided, the leftmost character is used for padding. All additional characters are always added rightmost. Additional characters are included in the given padding width. If the character count is zero nothing is added at all. The characters passed for padding must not contain characters with ASCII code less than 32, e.g. new line or tab.
READ_LEFT_TO_RIGHT macro keyword 
[ENTRY]["Name"][READ_LEFT_TO_RIGHT]
 Specifies that the table is to be read from left to right for this entry.
READ_TOP_DOWN macro keyword 
[ENTRY]["Name"][READ_TOP_DOWN]
 It specifies that the table is to be read from top down for this entry.
REGEX_REPLACE macro keyword Regular expression to match, Format expression 
[ENTRY]["File"][REGEX_REPLACE]['(.*)\.txt', '$1\.log']
 Before the entry is substituted the replace operation is performed on the text from the table entry.
REPLACE macro keyword Text to match, Text replacing the matched text 
[ENTRY]["File"][REPLACE][".tpl.", ".gen."]
 Before the entry is substituted the replace operation is performed on the text from the table entry.
STARTS_WITH macro keyword Text to match 
[ENTRY]["File"][STARTS_WITH]["Readme"]
 The substitution succeeds if the entry starts with the specified text.
TO_CSTRING macro keyword 
[ENTRY]["Parameter Value"][TO_CSTRING]
 Before the entry is substituted all special characters are converted to the correct escape sequences for c\c++ string literals, e.g. the new line character is converted to \n.
TO_CSV macro keyword The delimiters used and the char used for putting text items in quotes. 
[ENTRY]["State 1"][TO_CSV]["\t","\""]
 Before the entry is substituted the text content is put in quotes if it contains any of the delimiter characters or a new line character. The second parameter is optional. The default parameter for putting text items in quotes is the double quote character. If multiple quote chars are provided only the first character is used, but the text item is put in quotes if any one of the quote characters is found.
TO_LOWER macro keyword 
[ENTRY]["State 1"][TO_LOWER]
 Before the entry is substituted all characters are converted to lower case.
TO_SIZE macro keyword Additional properties needed for the determining the size value. 
[ENTRY]["State 1"][TO_SIZE]["array-elements"]
 Before the entry is substituted the text content is replaced by a size value. Currently only the property array-elements is supported. All characters are considered as Extended ASCII encoding. This will change in later versions. The text size is reported without a terminating zero. You can use the CALC tag to modify the value if needed.
TO_UPPER macro keyword 
[ENTRY]["State 1"][TO_UPPER]
 Before the entry is substituted all characters are converted to upper case.

Remarks: Aditional directives that can be placed behind the listed tag. Constraints for a successful substitution that can be placed behind the listed tag and it's additional directives. If multiple constraints are used then they are treated as if combined by an 'or'. To create an 'and' condition the substituted tag, e.g. ENTRY, has to be added multiple times to a macro preceded by an IF tag. Constraints can be prefixed with the NOT tag. The default constraint is [NOT][EQUALS][""]. One or multiple conversions can be applied to the substituted text. The conversions are performed in the order they appear. These tags can be placed behind the listed tag after additional directives or constraints.
